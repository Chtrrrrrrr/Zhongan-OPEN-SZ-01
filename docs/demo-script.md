## 2. A 段：3 分钟总结呈现（0:00–3:00）

**投屏内容**：一页"验收项 ↔ 结果"对照表（PPT 第 3 页，见 `docs/ppt-outline.md`）。

**口播脚本**（约 450 字）：

> 各位评委好。我们的命题是 OPEN-SZ-01，AI 生成材料反欺诈风控检测。先汇报对照验收项的当前结果：
>
> 第一，命题要求 100 套混合样本准确率 ≥95%、真实误报 ≤3%。这两个指标是耦合的——按 7:3 比例（70 真实 / 30 生成）推算，整批最多允许 2 个误报，同时 AI 检出率要 ≥93%。所以我们的主口径不是 Accuracy 本身，而是**低误报区间下的召回**；阈值在训练折的纯真实分数上按误报预算标定，绝不在测试集上调参。
>
> 第二，数据基础。命题给的 119 张样本我们做了完整盘查：56 张 AI、63 张真实，标签按文件顺序排列、只跳变一次，存在顺序泄漏风险；AI 类以数字渲染件为主、真实类以手机翻拍件为主，存在"渲染 vs 拍摄"捷径风险。这些偏置直接决定了我们的八条泄漏防护规则。47 维取证特征基线在本机复现为分层 5 折 × 5 种子平均 AUC **0.809**、最高单折准确率 **0.913**（与手册记录 0.916/85.7% 的差异原因已定位，见 `docs/l1-baseline.md`）——证明有信号，但低层线索不够，必须上深度模型。
>
> 第三，系统形态。分层可降级流水线：L0 输入解析、L1 低成本取证、L2 多路 AIGC 主检测、L3 篡改定位，最后融合校准、三档决策、输出结构化报告。MVP 保证最低可交付，增强模块以实测增益决定去留。
>
> 下面进入 7 分钟落地演示。

## 3. B 段：7 分钟落地演示（3:00–10:00）

> 每一步给出：操作 → 投屏要点 → 口播要点 → 预计耗时。总计 7:00，含 30 秒机动。

### 步骤 B1（3:00–3:45，0:45）数据盘查与泄漏防护展示【已验证】

- **操作**：打开数据盘查报告（`docs/data-audit.md` 渲染版），展示样本构成表、标签序贯跳变图、近重复分组结果；现场运行一次划分脚本 `python scripts/split_dataset.py --seed 42 --verify-frozen`，展示 exit=0 与 train/val/test 分层数量。
- **投屏要点**：119 张 / 56 AI / 63 真实；跳变仅 1 次；aHash≤6 近重复 77 对、4 个混标签组 22 张；D1–D8 规则表。
- **口播要点**："我们没有把命题样本当黑盒。盘查发现的三个偏置——序贯排列、渲染/拍摄捷径、容器指纹差异——每一个都有对应的防护规则，并且由脚本固化、可复现。"
- **兜底**：预计算截图 `demo/precomputed/audit-*.png`。

### 步骤 B2（3:45–4:30，0:45）L0/L1 取证管线现场运行【已验证】

- **操作**：对 1 张 AI 样本 + 1 张真实样本现场运行特征提取与基线：`python scripts/extract_features.py --input demo/samples/0xx.png`，展示 47 维特征与 PNG 块序列走查结果；再展示 L1 线索清单（命中/未命中/不可判三态）。
- **投屏要点**：容器指纹差异实例（sRGB 块、IDAT 块数、EXIF/XMP 有无）；单特征 AUC 排序（IDAT 0.719 / sRGB 0.685 / 块效应 0.678）。
- **口播要点**："L1 的作用是双重的：既是可解释证据，也是早退能力。但我们明确它只作辅助——这些容器指纹一次重编码就能抹掉，绝不能当主判据。"
- **兜底**：预计算 `demo/precomputed/l1-report-*.json`。

### 步骤 B3（4:30–5:30，1:00）L2 主检测现场推理【已验证】

- **操作**：服务常驻状态下，对 3–4 张样本（AI 渲染件 / 真实翻拍件 / 困难真实件各一）现场推理，实时展示两路证据分数与耗时。命令：`python scripts/predict.py --image ../data/images/001.png --out ../reports`
- **实际模型（以消融结果为准，不是以计划为准）**：
  - `forensic`＝L1(47 维) ⊕ L1b(20 维，拍摄态/渲染态取证) ⊕ patch-token(16 维)，OOF AUC **0.930**；
  - `combined`＝`forensic` ⊕ 冻结 CLIP-L/14 全局特征 ⊕ **6×6 原生分辨率分块 CLIP（mean/max 聚合）**，OOF AUC **0.975**；
  - **分块规格是搜索出来的、不是拍定的**：`python scripts/tile_clip_sweep.py` 覆盖网格/重叠/预缩放 × 5 种聚合 × 多尺度，
    结论是"网格越密越好（单调）"且 `mean/max` 优于 `mean/max/std`（证据：`reports/tile_clip_sweep.json`）；
  - **NPR 分支已实现但被消融剔除**：它在 18 生成器基准上 val AUC 0.850，迁移到本任务只有 0.569，加入融合使 AUC 由 0.9657 单调降到 0.9298（证据：`reports/npr_ablation.json`）。这正是"多模型不等于强"的实证，讲这一段比讲模型数量更有说服力。
  - 外部冻结探针（仅基准训练）在 119 张上 AUC 0.648，未达 0.65 准入线，被准入规则自动剔除。
  - **训练语料**：命题 119 张（`sample_weight=300`）⊕ 外部带标签语料 1561 张；外部影像只进训练折。
- **投屏要点**：两路分数并排、端到端耗时（实测全量 119 张热启动 P50 **1.17 s** / P95 **1.63 s**，预算 5000 ms）。
- **口播要点**："决定成败的不是模型数量，而是两个具体发现。第一，把整张单据缩到 224×224 会丢掉区分'数字渲染件 vs 手机翻拍件'的原生分辨率细节，改成分块 CLIP 之后单路 AUC 从 0.895 提到 0.965，网格加密到 6×6 再提到 0.975。第二，命题的'真实'类几乎全是手机拍的纸，模型学会的是'拍摄的纸=真'——我们在外部集上实测到 41 张真实事故照被 100% 误判，把外部真实影像补进训练负类之后，误报降到 0%，同时命题准确率还从 0.947 升到 0.959。"
- **兜底**：`reports/*.json` 预计算结果 + 预录推理片段。

### 步骤 B4（5:30–6:15，0:45）融合校准与三档决策【已验证】

- **操作**：展示评测证据 `reports/metrics.json` 与 `models/fix_metrics.json`；现场演示一个"待复核"档位样本（融合分数落入不确定带 → 系统主动转人工）。
- **实测口径（讲清楚，不回避）**：阈值取训练折**纯真实**分数的次序统计量，误报预算 `floor(0.03×70)=2`。折外结果（6 组 CV 种子）：准确率 **0.9594**（范围 [0.9496, 0.9664]）、误报 **2.12%**（折算命题 7:3 比例 **2.86%**）、召回 **0.9375**。单次运行（`reports/metrics.json`，seed=42）为 0.9496 / 3.17% / 0.9286。
- **必须主动说明的两点**：
  1. 命题给的 119 张是 47:53，与命题描述的 7:3 不一致。在 63 个真实样本上，1 个误报就是 1.59%，**根本没有 3% 这一档**。所以阈值按"每评测批最多 2 个误报"这一可跨集规模迁移的业务口径标定，两种口径都给出；同时把纯真实标定池扩到 **1103 张**（63 命题 + 1040 外部），把误报估计粒度从 1.59% 降到 0.09%，实测 **0/1103**。
  2. 两个真实总体（票据类 / 场景类）分数水平不同，无法共用一个精确工作点：`models/fusion.json` 同时记录官方阈值（已采用，命题折外 0.9594）与合并阈值（命题折外 0.9538），取舍写在文件里而不是藏起来。
- **投屏要点**：三档决策表；最优准确率-误报前沿（`operating_points_best_accuracy`）；"待复核是设计的一部分，不是系统失败"。
- **口播要点**："反欺诈场景里，一次错误的'确定造假'比一次转人工的代价大得多。我们的熔断原则是：宁可说无法判定，也不给不可信的结论。但也要说清楚：'待复核'不能当成误报的解药——真实场景照被 100% 误判这件事，我们是用补训练数据修的，不是靠把它们都塞进待复核。"
- **兜底**：预计算阈值标定记录表 + 三档样本报告。

### 步骤 B5（6:15–7:15，1:00）可解释性：定位图 + 结构化报告【待验证，P2/P3 填入】

- **操作**：展示 1 张疑似样本的完整结构化报告（按手册 9.2 字段，见 `assets/report-template.json`）：输入哈希、各模型分数、L1 线索清单、L3 异常区域定位图、Grad-CAM 关注区域（明确标注"关注区域 ≠ 伪造区域"）、不确定性与版本耗时。
- **投屏要点**：报告七个字段分组逐项过；定位图与 Grad-CAM 并排展示并强调性质区别。
- **口播要点**："报告回答的问题是'系统为什么得到这个结果'。定位分支输出异常区域，Grad-CAM 只说明分类器在看哪里——两者在报告里分开标注，不混为一谈。"
- **兜底**：预计算报告 JSON + 渲染 PDF。

### 步骤 B6（7:15–8:30，1:15）100 套批量评测与鲁棒性【待验证，P3/P4 填入】

- **操作**：运行批处理脚本对混合样本集一键评测（或展示最近一次冻结评测结果），输出指标表与失败案例清单 ⏳；展示鲁棒性矩阵（重压缩 Q95/85/70/50、缩放、截图、二次转存后的 TPR@FPR=1% 变化）⏳。
- **投屏要点**：Accuracy / FPR / TPR@FPR=1% / 混淆矩阵；冷热启动 P50/P95；鲁棒性矩阵热力图。
- **口播要点**："鲁棒性矩阵的目的不是证明所有线索永远有效，而是说清楚哪条线索先失效、失效后系统降权哪一路——这比一个不区分条件的分数更有工程价值。"
- **兜底**：预计算指标表 + 鲁棒性矩阵图（播放录屏）。

### 步骤 B7（8:30–10:00，1:30）视频检测 + 降级演示 + 收尾【待验证，P3 填入】

- **操作**：(a) 对 1 条 AI 生成视频与 1 条真实视频演示"16 帧均匀抽样 → 逐帧打分 → 聚合"流程与可疑片段定位 ⏳；(b) 现场演示一次降级：临时断开一路模型，系统跳过该路、照常出报告并标注"该证据项未参与判定"；(c) 收尾一页：当前状态 vs 验收项。
- **投屏要点**：视频逐帧分数曲线与聚合结果；降级前后报告对比（缺失模型清单字段）。
- **口播要点**："命题样本不含视频，所以视频通道是复用图像权重加时序聚合的工程方案，简单聚合有效才加码复杂模块。降级能力同理：5 秒是硬约束，任何单点故障都不能让系统整体失败。"
- **兜底**：视频演示全部使用预计算结果 + 录屏；降级演示预录片段。

## 4. 兜底方案总表

| 失效场景 | 触发条件 | 兜底动作 |
|---|---|---|
| 现场环境崩溃 | 服务无法启动 / 依赖报错 | 切换预计算结果包（`demo/precomputed/`：全部 JSON 报告 + 定位图 + 指标表），口播不停 |
| 推理现场超时 | 单样本 > 5 秒 | 切换同一样本的预计算报告，并说明"线上环境波动，以离线实测 P95 记录为准" |
| 视频解码失败 | 抽帧报错 | 播放预录视频检测片段；标注降级路径（首/中/尾三帧） |
| 网络/投屏故障 | 腾讯会议中断 | 本地录屏继续，事后补发录屏与报告包 |
| 评委要求复现 | 现场要求重跑某样本 | 优先现场重跑；环境异常时给出该样本输入哈希 + 预计算报告哈希对照 |
| 版本质疑 | 评委质疑结果可复现性 | 展示权重哈希、阈值版本、输入哈希、划分冻结签名（`data/splits_frozen.json`） |

> 兜底纪律：使用预计算结果时必须明示"以下为预计算结果"，不把兜底包装成现场实测（对应风险 R12 预案）。

## 5. C 段：5 分钟问答（10:00–15:00）预设问答

| # | 预设问题 | 回答要点 |
|---|---|---|
| 1 | 95%/3% 现在达到了吗？ | 诚实口径：当前处于铺垫/管线阶段，已验证的是数据盘查、划分协议与 L1 基线（AUC 0.916）；最终数字在模型/阈值/划分/权重四项冻结后一次性评测给出，不提前承诺。【若 P4 已完成则报实测值 ⏳】 |
| 2 | 误报怎么压到 3% 以内？ | 纯真实校准集定阈值 + bootstrap 区间 + 独立真实留出集验证；单据类可单独校准；超护栏预案是收紧高档条件为"分数超阈 + 至少两条独立线索命中"。绝不在测试集搜阈值。 |
| 3 | 换一个新生成器会不会崩？ | 不承诺对所有新生成器保持同一性能；给出可复现的跨生成器下降曲线与快速迭代路径（冻结骨干 + 轻量头，新增一路只需训练轻量头并加入校准流程）。 |
| 4 | 为什么不用商用检测 API？ | 与"单机可复现"要求冲突，指标无法独立验证；AI 原生度要求的是自有检测能力。 |
| 5 | 视频没有训练数据怎么办？ | 复用图像权重逐帧 + 最简聚合先行；公开视频集验证；复杂时序模块有 Go/No-Go 门槛，不过就降级为逐帧检测 + 可疑片段 + 人工复核并标注局限。 |
| 6 | 5 秒怎么保证？ | 模型常驻预热、级联早退、按"最廉价成员优先"排序、累计预算熔断；以冷/热启动各 ≥20 次的 P95 实测为准 ⏳。 |
| 7 | 可解释性体现在哪？ | 报告七个字段分组；L1 离散线索三态清单；L3 异常区域定位；Grad-CAM 单独标注为关注区域解释；每个结论附不确定性与已知局限。 |
| 8 | 命题样本 119 张拿来训练了吗？ | 原则上只用于链路自检、偏置分析与最终测试依据之一；调参在独立验证集/校准集完成（防 R10：命题样本过度使用）。 |
| 9 | 三人团队怎么分工？ | 数据与评测 / 算法与模型 / 工程与集成三线并行；模型取舍、融合权重、阈值由全队共同确认。 |
| 10 | 定位图会不会误导？ | 三条定位路径（TruFor / patch 聚合 + Grad-CAM / L1 线索）互相校验；真实样本频繁高亮时降级为"仅疑似样本提供定位图"并强制附局限声明。 |

## 6. 彩排与冻结要求

2. 上场前冻结：代码 commit、模型清单与权重哈希、阈值版本、演示样本清单与输入哈希、预计算包哈希；
