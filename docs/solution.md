## 1. 命题解读

### 1.1 命题要求（【命题约束/验收标准】）

针对理赔等场景中 AI 生成的虚假图片和视频构建反欺诈检测能力，命题验收项如下：

| 验收项 | 标准【验收标准】 | 方案落实方式 |
|---|---|---|
| 综合准确率 | 100 套混合样本（真/假约 7:3）识别准确率 ≥ 95% | 冻结模型、融合权重与阈值后，对规定样本一次性评测 |
| 误报控制 | 真实材料误报率 FPR ≤ 3% | 纯真实校准集标定阈值 + 独立真实留出集验证，不在最终测试集调阈值 |
| 类型覆盖 | 支持图片 + 视频，覆盖 ≥ 3 种 AIGC 工具 | 图片主链路 + 视频逐帧复用时序聚合；测试按生成器分组报告 |
| 响应速度 | 单张图 / 单条视频 ≤ 5 秒 | 模型常驻预热、级联早退、限制抽帧、超时降级；报告 P50/P95 |
| 可解释性 | 伪造区域可定位、判定依据可说明 | L1 离散线索清单 + L3 异常区域定位 + 结构化报告 |
| AI 原生度红线 | 多模态 + 伪造痕迹检测 + 元数据分析 + ensemble（一票否决） | 架构四要素齐备，可现场逐项演示 |

### 1.2 指标耦合：为什么不能只看 Accuracy

95% Accuracy 与 3% FPR 不是两个可分别"凑到"的指标。以评测集真/假约 7:3 为例：真实样本约 30 张时，FPR ≤ 3% 意味着**最多只能误判 0 张真实样本**；此时 Accuracy ≥ 95% 又要求 AI 样本至少检出 65/70，即 **AI 类召回率 TPR ≥ 92.9%**。无论类别比例取何值（0.3–0.7 区间），两个指标联合起来都要求 AI 类召回率不低于约 90%。

因此本方案把 **TPR@FPR=1%** 作为内部主口径指标，同时保留 Accuracy、FPR、混淆矩阵与固定阈值结果；优化直接围绕"低误报下的高召回"展开，而不是先追 Accuracy 再压误报。

### 1.3 判定边界声明

方案将"材料是否由 AI 生成或经过篡改"（技术判定，本方案负责）与"理赔事实是否成立"（业务判定，不在范围内）分开。系统输出「正常 / 待复核 / 疑似生成或篡改」三档结论及判定依据，不直接给出业务上的"欺诈"结论；对外表述统一采用"疑似生成合成内容"口径，与 2025 年 9 月 1 日施行的《人工智能生成合成内容标识办法》保持一致。

## 2. 数据盘查结论【已验证】

命题给定样本（文件 3，`AI生成材料反欺诈风控检测.xlsx`）并非可直接使用的干净训练集，而是一份先做数据审计的样本包。完整盘查过程与独立重推校验见 **[数据盘查报告](../../docs/data-audit.md)**（工作区 `docs/data-audit.md`，由 `scripts/build_audit.py` 自动生成、可复现）。关键事实：

### 2.1 样本构成事实

| 项目 | 结果【已验证】 |
|---|---|
| 样本总数 | **119 张**，全部为 PNG 图片，**无视频样本** |
| AI 生成类 | **56 张**（47.1%） |
| 真实类 | **63 张**（52.9%） |
| 类别比例 | 约 47:53，与命题评测集"真/假约 7:3"**不一致** → 阈值标定须用纯真实校准集，不可按本集比例外推 |
| 标签排列 | seq 1–56 为 AI、57–119 为真实，标签序列仅 **1 次跳变** → 任何切分前必须先打乱（D1） |
| 内容构成 | 中文医疗票据、病历、发票、费用清单为主，少量财产损失场景照 |
| 采集方式 | AI 类以数字渲染件为主（约 8 张场景照）；真实类几乎全部为手机翻拍件 → 存在"渲染 vs 拍摄"捷径风险 |
| 完全重复 | sha256 比对 **0 对** |
| 感知哈希近重复 | aHash 汉明距离 ≤ 6 共 **77 对**；其中 **4 个混标签组共 22 张**（同版式单据跨类出现），已由 D4/D5 规则原子分配防泄漏 |
| 像素/体积中位数 | AI 类 2.58 MP / 1359 KB；真实类 1.76 MP / 1194 KB |

### 2.2 容器指纹差异（仅作 L1 辅助线索）

| 容器特征 | AI 生成类（n=56） | 真实类（n=63） |
|---|---|---|
| 携带 sRGB 色彩块 | 42 张（75%） | 24 张（38%） |
| 携带 eXIf / iTXt（XMP） | 0 张 | 14 张（22%） |
| 携带 gAMA / cHRM | 0 张 | 5 张（8%） |
| PNG IDAT 块数 > 200 | 18 张（32%） | 9 张（14%） |

这些差异反映的是两条不同的图像生产与落盘流水线，一次重编码/截图/转存即可抹除，因此**只作 L1 辅助证据，不作为主判据**。

### 2.3 先导基线实验【已验证】

47 维低层/容器取证特征 + L2 正则逻辑回归，分层 5 折交叉验证 × 5 随机种子：

- 平均 AUC **0.916**，最高交叉验证准确率 **85.7%**（各折 80.0/87.5/87.5/91.3/91.3%）；
- 最强单特征：IDAT 块数（AUC 0.719）、sRGB 块（0.685）、8×8 块效应（0.678）——均为压缩器指纹，属最易被重编码抹除的线索；
- 结论：数据中存在可利用信号，链路可复现；但**仅依赖容器与低层取证特征不足以达到命题指标**，深度视觉特征与多模型互补的必要性由此确立，不预设其必然达标。

### 2.4 盘查结论对方案的约束

本题难点不在"找一个高分模型"，而在让模型不依赖数据集捷径。后续所有模型比较都必须放在**控制了生成器、采集方式和同源样本泄漏之后**进行（见 §6 验证方法）。

## 3. 系统架构

### 3.1 端到端流水线

```
输入（图片 / 视频）
   │
   ▼
┌──────────────┐   ┌──────────────┐   ┌───────────────────┐   ┌──────────────────┐
│ L0 输入解析   │ → │ L1 低成本取证 │ → │ L2 AIGC 主检测     │ → │ L3 篡改检测与定位 │
│ 解析/解码/规范化│   │ 元数据/容器/压缩│   │ NPR + CLIP/AIDE    │   │ TruFor 异常图/掩膜 │
│ 哈希/合法性    │   │ 频域/统计线索  │   │ (+Effort/AEROBLADE)│   │ (+Grad-CAM 解释)  │
│  预算 <0.1s   │   │  预算 <0.3s   │   │   预算 <1.5s       │   │   预算 <1.0s      │
└──────────────┘   └──────────────┘   └───────────────────┘   └──────────────────┘
       │                  │                     │                       │
       ▼                  ▼                     ▼                       ▼
┌───────────────────────────────────────────────────────────────────────────┐
│ 决策层：多证据融合 → 置信度校准 → 三档决策 → 结构化报告                      │
│ 输出：正常（低风险）/ 待复核 / 疑似生成或篡改（高风险）                       │
└───────────────────────────────────────────────────────────────────────────┘
```

各层是"证据生产者"而非串行关卡：某一路超时或异常时可被跳过，其余证据继续形成结论（降级原则见 §5.3）。

### 3.2 各层职责边界

| 层 | 职责 | 明确不做 | 预算目标 | 失效影响 |
|---|---|---|---|---|
| **L0 输入解析** | 格式解析、图片/视频解码、尺寸与色彩统一（模型输入最长边 512）、内容哈希（sha256 + 感知哈希）、合法性检查 | 不承担任何检测 | < 0.1 s | 无（可降级为统一处理） |
| **L1 低成本取证** | 元数据、PNG 块序列、EXIF/XMP、JPEG 重压缩、ELA、CFA、频域与上采样、图像统计（47 维） | 不单独构成判定依据 | < 0.3 s | 损失可解释性与早退能力，不影响 L2 判别 |
| **L2 AIGC 主检测** | 多路深度检测模型推理打分 | 不做像素级定位 | < 1.5 s | 主要判别力下降，靠 L1 与决策层兜底 |
| **L3 篡改检测与定位** | 篡改检测、异常区域热力图/掩膜、必要的关注区域解释 | 不替代 L2 的 AIGC 判定 | < 1.0 s | 损失定位能力与部分可解释性 |
| **决策层** | 分数校准、证据融合、三档判定、报告生成 | 不引入新检测模型 | < 0.1 s | 无（决定性环节） |

### 3.3 L2 模型选型：少而互补，而不是多而完整

| 成员 | 定位 | 依赖信号 | 待验证问题 |
|---|---|---|---|
| **NPR**（CVPR 2024） | Core | 上采样操作在相邻像素间留下的强相关模式 | 在中文单据、低质量翻拍件上的实际区分力 |
| **CLIP 线性探针 / AIDE**（ICLR 2025） | Core | 冻结 CLIP 语义特征 + 高低频 patch 线索 | 二者谁更稳定、是否值得同时保留 |
| **Effort**（ICML 2025） | Optional | 冻结主成分、只微调残差子空间 | 相对 Core 是否带来稳定 ΔTPR@FPR=1% |
| **AEROBLADE**（CVPR 2024） | Optional | SD-VAE 重建误差（免训练） | 对非 SD 家族生成器是否具备区分力 |
| **TruFor**（CVPR 2023） | L3 定位主力 | RGB + Noiseprint++ 双流，输出异常图与置信度图 | 定位图在真实样本上是否频繁误高亮 |

**保留规则**：新增一路模型必须在相同测试协议下带来稳定的低 FPR 区域增益，且其错误不能与已有模型高度重叠（留一法 Δ + 错误集合交并比判定）；否则不为"模型数量"支付额外耗时与维护成本。备选：CAT-Net、PSCC-Net 列为 L3 备选；零权重取证线索（ELA/JPEG ghost/CFA/噪声方差）必选为辅证。

### 3.4 视频通道：先简单、后复杂

命题样本不含视频【已验证】，视频能力属【待验证】工程方案：

- **阶段 1（最简路径）**：视频 → 16 帧等间隔均匀抽样 → 图像检测器逐帧打分 → 均值/中位数/P90/标准差聚合 → 视频级分数 + 可疑片段；
- **阶段 2**：仅当阶段 1 在公开视频数据集上被证明有效后，才加入 flicker 统计与光流残差；
- **Go/No-Go**：若复杂时序模块无稳定增益，则降级为"逐帧检测 + 可疑片段定位 + 人工复核"，并在报告中明确标注局限，不追求形式上的视频全自动。

### 3.5 决策层：融合、校准与三档输出

- **融合方式**【工程假设】：各路先温度缩放校准到同一尺度 → logit 层面加权平均 → 集成后再校准一次；权重在独立验证集上确定，不使用最终测试集。
- **三档输出**：

| 档位 | 判定逻辑（标定后冻结） | 处理含义 |
|---|---|---|
| 正常（低风险） | 融合分数低于低档阈值，且无明显取证异常 | 常规通过，保留结果与基础证据 |
| 待复核 | 模型间明显分歧 / 分数落入不确定区间 / 属已知高误报场景（翻拍、低照度、反光）/ 定位置信度不足 | 交人工复核——这是设计的一部分，而非系统失败 |
| 疑似生成或篡改（高风险） | 多个证据方向一致且超过高档阈值，或出现明确异常 | 提交业务侧核查，不直接认定理赔欺诈 |

- **熔断原则**：宁可输出"待复核/无法判定"并转人工，也不在证据不足时给出过强结论。

## 4. MVP / Enhanced 双轨交付策略

方案从一开始就划分两条交付轨道：**MVP 是承诺交付的下限，Enhanced 是条件允许时的增量**。即使全部增强模块未能按期稳定，MVP 仍是一套结构完整、可现场演示、可给出结论与依据的图片检测系统。

| 模块 | MVP | Enhanced | 必须性 |
|---|:-:|:-:|---|
| L0 输入解析 | ✓ | ✓ | 必须 |
| L1 取证线索（47 维） | ✓ | ✓ | 必须 |
| L2 Core：NPR | ✓ | ✓ | 核心 |
| L2 Core：CLIP / AIDE | ✓ | ✓ | 核心 |
| 多证据融合与校准 | ✓ | ✓ | 必须 |
| 三档决策与结构化报告 | ✓ | ✓ | 必须 |
| L2 Optional：Effort | — | ✓ | 可选（消融决定去留） |
| L2 Optional：AEROBLADE | — | ✓ | 可选（消融决定去留） |
| L3 定位：TruFor | — | ✓ | 建议（支撑"伪造区域标注"验收项） |
| L3 解释：Grad-CAM | — | ✓ | 建议（辅助解释，不等同于定位） |
| 视频通道 | — | ✓ | 按时间决定 |
| 完整鲁棒性矩阵 | — | ✓ | 建议 |

**双轨原则**：增强模块以实测增益为准决定去留，不以模块数量作为系统质量评价标准。

## 5. 工程设计与降级

### 5.1 性能预算与 5 秒约束

单材料 ≤ 5 秒为【命题约束】。工程手段：模型常驻进程并预热（避免首次框架初始化占用预算）、级联早退（最廉价成员优先）、限制抽帧数、逐模块时间预算。耗时验收以目标机**冷/热启动各 ≥20 次重复实测的 P50/P95** 为准，不以平均值替代【待验证】。

### 5.2 当前已落实的工程产物（铺垫阶段）

- `src/l0_input.py`：L0 解析与规范化（PNG 块序列走查、sha256 + 16×16 aHash、最长边 512 缩放、双分辨率输出）；
- `src/l1_forensics.py`：47 维 L1 取证特征（色彩 9 / 纹理梯度 8 / 噪声残差 6 / 自相关 4 / 块效应 3 / 通道相关 3 / 多尺度残差 4 / 容器 9 / 宽高比 1）；
- `scripts/extract_features.py`、`scripts/baseline_l1.py`：特征批提取与先导基线复现（5 折 × 5 种子）；
- 数据侧（工作区）：119 张样本提取与逐字节 sha256 校验、`split_dataset.py`（D1–D8 划分协议）、`build_audit.py`（可复现审计）。

### 5.3 降级与熔断

| 触发条件 | 熔断动作 | 降级后输出 |
|---|---|---|
| 某路模型加载失败 | 跳过该路并标记"不可用" | 其余路正常融合，报告列出缺失模型 |
| 某路推理超时 | 中断该路，使用已完成中间结果 | 报告标注"该证据项未参与判定" |
| 累计耗时接近预算 | 停止加载后续 Optional 成员 | 基于部分证据的结论，下调置信度 |
| 图像无法解码/损坏 | 返回"无法判定" | 交人工复核，不强行给结论 |
| 视频抽帧失败 | 退化为首/中/尾三帧 | 置信度下调并标注局限 |
| 深度模型全部不可用 | 退化为"L1 线索 + 阈值"模式 | 明确标注为降级模式 |

## 6. 验证方法与指标

### 6.1 数据划分与泄漏防护（D1–D8）

| 编号 | 规则 | 目的 |
|---|---|---|
| D1 | 任何划分之前先打乱 | 消除命题样本的类别序贯排列（实测跳变仅 1 次） |
| D2 | 按生成器分层 | 保留训练未见生成器做测试，检验真实泛化 |
| D3 | 按采集方式分层（渲染态/拍摄态） | 防止"渲染 vs 拍摄"成为捷径特征 |
| D4 | 感知哈希去重（aHash ≤ 6 近重复组原子分配） | 排除同源样本跨集合泄漏（本集实测 77 对近重复、4 混标签组） |
| D5 | 同源翻拍/裁剪/重压缩版本不得跨 train/val/test | 阻断记忆泄漏 |
| D6 | 阈值标定不得使用最终测试集 | 提高误报率估计可信度 |
| D7 | 融合权重与模型选择不得在最终测试集上搜索 | 避免模型选择层面的过拟合 |
| D8 | 最终报告只使用冻结后的模型与阈值 | 使结果可复现 |

> **泄漏红线**：在最终测试集上搜索最佳阈值、或依据最终测试集分数分布调整融合权重与模型组合，均属评测泄漏，本方案明确禁止。

### 6.2 指标体系

| 层级 | 指标 | 用途 |
|---|---|---|
| 命题验收指标 | 综合准确率、FPR、单材料耗时 | 直接对应【验收标准】 |
| 护栏与操作点 | **TPR@FPR=1%（主口径）**、FPR@TPR=95%、固定阈值 Precision/Recall、ECE | 低误报下的 AI 检出能力 |
| 诊断指标 | 分生成器/分采集方式/分内容拆解、分数相关性矩阵、逐层消融、耗时拆解 | 定位问题，不对外承诺 |

### 6.3 阈值标定流程（bootstrap 稳定性）

1. 建立**纯真实校准集**（含中文单据渲染态与翻拍态、低照度、反光、模糊、褶皱等困难负样本）；
2. 冻结全部模型参数与融合权重（记录版本与权重哈希）；
3. 在校准集上获得真实样本分数分布，以目标 FPR 对应经验分位数作为**初始**阈值估计；
4. 对校准集 **bootstrap 重采样**重复估计阈值，记录中位数与 95% 置信区间；
5. 在**独立纯真实留出集**上验证实际经验 FPR；
6. 通过后冻结阈值并记录版本；最终在测试集上**只评测一次**。

> 表述纪律：不把"取 99 分位即等于 FPR=1%"当等式使用；报告须同时给出阈值、校准集规模、经验 FPR、bootstrap 区间与阈值敏感性。

### 6.4 模型组合实验与鲁棒性

- **组合协议**：单路（L1 / NPR / CLIP/AIDE / Effort / AEROBLADE）→ 逐步加入（ΔTPR@FPR=1% 曲线）→ 留一法（Leave-one-out Δ）；同时记录分数相关性、判定分歧度、误报/漏报集合重叠度——只有"修正了其他路已经犯下的错误"的路才进入最终版本。
- **鲁棒性矩阵**：JPEG 重压缩（Q95/85/70/50）、分辨率缩放（长边 1024/512 后放大）、截图重采样、二次转存（IM 压缩链路）、噪声与模糊——目的是明确"哪条线索先失效"并据此降权，而非预期所有线索永远有效。
- **错误分析**：每轮实验建立错误档案并按维度归因（FP：翻拍/低照度/模糊/反光/褶皱/重压缩/截图/电子文档；FN：生成器/生成方式/内容/分辨率/压缩/后处理），错误驱动增删模块，而非"分数不够就再加一个模型"。

### 6.5 最终结论给出条件

模型冻结 + 阈值冻结 + 数据划分冻结 + 融合权重冻结四项全部满足后，才进行一次性最终评测并对 95% / 3% / 5 秒 / ≥3 种工具给出结论；在此之前一律以【验收标准】表述。
